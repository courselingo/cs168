## 一、规模问题，出在「一个目的地一行」上

前面几讲一直默认转发表是「一个目的地一行」。这一讲要解决的就是这件事撑不住的问题。

> "So far, our forwarding table has one entry per destination. This won't scale to the entire Internet."
> （到目前为止，我们的[[term:forwarding]]（forwarding，转发）表一个目的地一行。这撑不到整个[[term:internet]]（Internet，互联网）。）

教材把两条路都算了一遍：在全世界跑距离向量，就得为互联网上的每一台主机发一条宣告；跑链路状态，就得让每台路由器都知道整个互联网的图。而且只要有任何一台主机加入或离开，都得重新算一遍、重新收敛。出路不在协议上，在编址方式上：前面我们管每台机器叫 R1、R2、A、B，现实中要用一套聪明得多的编号办法。

![一个目的地一行撑不到整个互联网：宣告数量与计算量都会爆掉](figures/addr-1.svg)

出路的直觉来自邮政系统。同一个包裹，快递员用「Hearst 大道 2551 号」，楼里的秘书用「Soda 楼 413 室」，不同场合用不同的编址方式，而且地址是按结构分配的：三楼房间号都以 3 开头，四楼都以 4 开头。

互联网在各层也用不同的编址方式，这一讲只讲[[term:ip-address]]（IP address，IP 地址），它服务于第三层的[[term:routing]]（routing，路由）：网络上每台主机（你的电脑、Google 的服务器）都有一个唯一的 IP 地址，而它的数字里带着「这台机器在哪」的信息。

有两点要顺手记住。第一，IP 地址不一定固定：人搬家地址会变，机器换个位置接入网络也可能拿到新的 IP 地址，旧地址最终会过期。第二，地址长度取决于版本：IPv4 是 32 位，IPv6 是 128 位；两版的路由思路相同，教材尽量用 IPv4，因为短一点好读。

![IP 地址像邮政地址：数字里带着位置信息，而且不一定是固定的](figures/addr-2.svg)

地址的价值不在编号本身，而在于它能被概括。

## 二、分层编址：**网络 ID** 加**主机 ID**

互联网本来就是「网络的网络」，这个天然层次正好用来组织地址：先给每片网络一个号，网络 3 里的主机就叫 3.1、3.2、3.3……

好处立刻体现在[[term:router]]（router，路由器）的表里。以前 R9 要为网络 1 里的每台主机写一行，而且下一跳都是 R6；分层编址之后，它可以只写一行：所有 `1.*` 的地址走 R6。

> "This hierarchical model, where we use wildcard matches to summarize routes, makes our forwarding tables smaller."
> （这种用通配符匹配来概括路由的分层模型，让转发表变小了。）

教材还给了第二个好处：表更稳定。网络 1 内部怎么变（比如新主机加入），R9 及其他网络的表都不用动。而现实中域内的变化（新机器上网）远比域间的变化（新铺一条地下光缆）频繁，所以「本地变化只影响本地表」是件大好事。

一般化地说，地址由两部分组成：网络 ID 与主机 ID。域间路由协议看网络 ID 找网络之间的路，域内路由协议看主机 ID 找网络内部的路。这也让协议各安其位：域间协议不关心网络内部的变化，域内协议不关心别的网络的变化。

要注意一个边界：R9 对自己所在网络里的主机仍然要逐台写条目。所以一张表的规模，大致等于「同网络内的主机数 + 外部网络数」。

![地址分两段：域间看网络 ID，域内看主机 ID](figures/addr-3.svg)

两段地址的分工，正是「域间看网络、域内看主机」这句话的来源。

## 三、**默认路由**：剩下的都交给一个人

既然一行可以代表一整个范围，那还能再往前走一步。R4 为每个外部网络（1.\*、3.\*、4.\*）都写了一行，而下一跳全是 R9，那就可以把它们合并成一行：凡是不在表里的，都交给 R9。

R2 上可以合并得更激进：外部网络下一跳都是 R3，而内部的 2.1、2.2、2.3、2.6、2.7 下一跳也是 R3，于是表里只需留下 2.4 与 2.5 两行，其余全部交给 R3。代表「所有不在表里的地址」可以用一个通配符 `.`。转发时先查具体主机（如 3.1）或范围（如 2.），都匹配不上才落到 `*`。

> "This is called the default route."
> （这就叫默认路由。）

这条规则还解释了一件前面提过的事：大多数主机只有一条硬编码的默认路由。主机 2.4 的表里只有一行「全部交给 R2」，你家电脑的表里只有一行「全部交给家里的路由器」，这就是主机不必参与路由协议的原因。

![默认路由：先查具体与范围，最后落到通配符，其余的统统交给一台路由器](figures/addr-4.svg)

默认路由把「剩下的」交给一台路由器，这是让表变小的最后一步。

## 四、两种早期做法：8 位网络 ID 与分类编址

要让路由[[term:scalability]]（scalability，可扩展性），地址就必须按层次分配，也就是地址里得带位置信息（相邻主机共享地址的一部分）。教材按时间讲了三种做法。

最早：IPv4 地址是 8 位网络 ID + 24 位主机 ID。比如 AT&T 的网络 ID 是 12，Apple 是 17，美国国防部有 13 个网络 ID。问题有两个：8 位只能表示 256 个网络，而现实中想自己运营网络的组织远不止 256 个；同时 24 位主机 ID 意味着每片网络有 2^24 = 16,777,216 个地址，一个十来人的小公司根本用不上。

第一次修补是分类编址：按需要分三种规模的网络，用开头 1 到 3 位来标识属于哪一类。

- A 类：首位是 0，接着 7 位网络 ID（128 个网络），再 24 位主机 ID（1600 万台主机）。
- B 类：开头是 10，接着 14 位网络 ID（16,000 个网络），再 16 位主机 ID（65,000 台主机）。
- C 类：开头是 110，接着 21 位网络 ID（200 万个网络），再 8 位主机 ID（256 台主机）。

合起来能表示 200 万 + 16,000 + 128 个网络，大组织拿 A 类、小组织拿 B 或 C 类。但问题也很直白：每一类的规模都不合用，A 类 1600 万台对绝大多数组织太大，C 类 256 台又太小，于是大家都挤在 B 类。而 B 类网络 ID 只有 16,000 个，到 1994 年就用完了。

教材还补了两个细节：分类编址在今天已经废止；而每种网络的可用主机数严格说都要减 2，因为全 0 与全 1 的地址被留给特殊用途，C 类其实是 254 台，不是 256 台。

![分类编址：三类各自的位数，以及「太大、太小、都用 B 类」的死结](figures/addr-5.svg)

三类网络各自都不合用：失败的原因不是位数不够，而是只有三档可选。

## 五、CIDR：网络 ID 的长度随便定

第三次、也是今天仍在用的办法是 CIDR（Classless Inter-Domain Routing，无类域间路由）。它保留变长网络 ID 的思路，但固定位数可以是任意值，不再只有三类。

教材举了两个例子。那个十人的小公司，在分类编址下会拿到一个 256 地址的 C 类；如果给它 28 位网络 ID，主机 ID 只剩 4 位（16 个地址），虽然浪费 6 个，但比 256 好得多。另一个需要 450 个地址的组织，C 类的 256 不够用、B 类的 65,000 又浪费太多；给它 23 位网络 ID，主机 ID 9 位（512 个地址），刚好够用。

![CIDR：同样的需求，位数按需切，浪费远小于分类编址](figures/addr-6.svg)

CIDR 的关键不是省地址，而是让地址块的大小能跟着需求走。

## 六、多层分配：从 ICANN 一直到主机

现实中的层次不止一层。机构内部还会把地址段分给下级单位（公司的部门、大学的院系）。教材把实际的分发链条讲了一遍：ICANN（Internet Corporation for Names and Numbers）拥有全部 IP 地址；它把地址块发给代表国家或地区的地区互联网注册局（RIR），比如 RIPE 管欧盟、ARIN 管北美、APNIC 管亚太、LACNIC 管南美、AFRINIC 管非洲；RIR 再把其中一部分发给大组织或 [[term:isp]]（ISP，互联网服务提供商）（这类机构叫本地互联网注册局）；最后由它们把单个 IP 分给具体主机。为了更细的层次，本地注册局也可以把地址段再分给小组织，由小组织继续往下分。

每一层固定多少位，取决于要分出去多少个地址。教材的例子是：ARIN 想给 AT&T 800 万个地址，算下来固定 9 位就够；它自己已经固定了 4 位，于是再固定 5 位，把以这 9 位开头的所有地址给 AT&T；AT&T 再拿出前缀 `1101 11001 110100010` 给 UC Berkeley，那是 16,000 个地址。注意父机构固定过的那几位会被一直保留，越往下分、固定的位越多。

![多层分配：ICANN → 地区注册局 → 本地注册局 → 主机，固定的位数一层层加长](figures/addr-7.svg)

分发的每一层都只多固定几位，前缀天生就带着层次。

## 七、地址怎么写：点分十进制、斜杠与掩码

地址可以写成 32 位的 0/1 串，也可以写成一个很大的整数；为了好读，实际做法是每 8 位写成一个 0 到 255 的十进制数，比如 `00010001 00100010 10011110 00000101` 写成 `17.34.158.5`，这种写法叫点分十进制。

要写一个范围，用斜杠记法：先写固定的前缀，未固定的位全部补 0，转成点分十进制，再在斜杠后面写上固定了多少位。例如前缀是 `11000000`，补零后是 `192.0.0.0`，于是这个范围写成 `192.0.0.0/8`。单个地址可以写成 `192.168.1.1/32`（32 位全固定），默认路由那个通配符可以写成 `0.0.0.0/0`。

斜杠记法有一处容易看花眼，因为它用的是 8 位分组加十进制。比如 8 位前缀 `11000000` 与 12 位前缀 `11000000 0000`，写成范围都是 `192.0.0.0/8` 与 `192.0.0.0/12`，同一个 IP 地址代表两个不同的范围。再如你拥有 4 位前缀 `1100`、把它下面的 5 位前缀 `11001` 分出去，写成范围分别是 `192.0.0.0/4` 与 `200.0.0.0/5`，光看这两个字符串根本看不出后者是前者的子集，得把二进制写出来才能确认。

斜杠还有另一种写法叫网络掩码（netmask）：固定的位写 1、未固定的位写 0，再转成点分十进制。比如 `192.168.1.0/29` 是 29 个 1 加 3 个 0，写成 `255.255.255.248`。掩码有用的地方在于：拿 IP 地址与掩码做按位与，主机位会被清零，只剩网络位。

![斜杠记法：同一个 IP 地址可以代表不同范围，光看字面看不出包含关系](figures/addr-8.svg)

斜杠与掩码是同一件事的两种写法，读的时候都要把二进制在脑子里展开。

## 八、用 CIDR 把多条路由聚成一条

最初的分层模型能把同一片网络里的主机聚成一条路由（比如 2.\* 代表网络 2 的全部）。多层分配之后，还能把多片网络聚成一条。

教材的图里，R6 原本要为 AT&T、UCB、Stanford 各写一行。但如果 UCB 的 `4.12.0.0/16` 与 Stanford 的 `4.29.0.0/16` 都是 AT&T 的 `4.0.0.0/8` 的子集（也就是 AT&T 把这两段分给了下属客户），那么 R6 就只需要一行：AT&T 及其下属全部走同一个下一跳。

![聚合：两个小范围落在同一个大范围里，于是三条路由并成一条](figures/addr-9.svg)

聚合能成立的前提，是分配的层次和网络的组织方式对得上。

## 九、多宿：聚合不是万能的

聚合有失效的时候。假设我们给 R6 直接加一条到 Stanford 的[[term:link]]（link，链路）：原来那条聚合路由说「所有去 AT&T 及其下属的[[term:packet]]（packet，分组）走 R2」，现在必须再加一行，说明去 Stanford 的走 R7。

于是转发表里出现了互相重叠的范围。这时就得有一条规则来裁决，也就是最具体的那条优先：先匹配范围更窄的条目，匹配不上再退到更宽的范围，最后才是默认路由。

![多宿：直接连一条链路之后范围重叠，靠「最具体的优先」来裁决](figures/addr-10.svg)

一旦出现重叠，转发表就不再是「一个前缀一条」那么简单了。

## 十、IPv6：为什么换，以及它怎么写

IPv4 的地址空间迟早不够用，于是有了 IPv6：128 位地址。教材指出，这个空间大到可以简单地把网络 ID 固定成 64 位、主机 ID 固定成 64 位，两边都永远用不完；甚至存在这样的协议，让网络与主机自己挑一个 64 位的前缀、只要确认没被别人占用，不需要某个机构来分配。

实践中还是分层分配：地区注册局通常给 ISP 分 32 位前缀，ISP 通常给组织分 48 位前缀，组织再给更小的子网分 64 位前缀。IPv6 里一般见不到比 /64 更长的前缀，最细的子网也是 64 位前缀加 64 位主机位。统一的前缀长度还有一个附带好处：前缀变得更有信息量。在 IPv4 里一个 /19 代表什么要看情况，而在 IPv6 里，看到 /32 通常就知道那是一个 ISP。

## 十一、脉络回顾

这一讲解决的是「路由表装不下」的问题，而办法不在协议上，在编址上。地址分两段：网络 ID 与主机 ID，域间协议看前者、域内协议看后者，于是用通配符就能把一整片网络概括成一行，表既更小也更稳定。再往前一步是默认路由：先把能概括的概括掉，剩下的统统交给一台路由器，这也是端主机只需要一条硬编码路由的原因。

分配方式走过三代：8 位网络 ID 太少、每片网络又大得离谱；分类编址把网络分成 A/B/C 三类，结果大组织嫌小、小组织嫌大，大家都挤 B 类，1994 年就耗尽了；今天的 CIDR 把网络 ID 的长度变成任意值，按需切多少位，浪费远小于分类编址。真实的分发是多层的：ICANN 到地区注册局，到本地注册局，再到具体主机，父机构固定过的位一路保留。写法上有点分十进制、斜杠与网络掩码，而斜杠记法同一串字符可以代表不同范围，读的时候要当心。多层分配让 CIDR 能把多片网络聚成一条路由，但多宿会让范围重叠，这时靠「最具体的优先」裁决。最后，IPv4 空间不够用，换成了 128 位的 IPv6。

## 读完应该能回答

1. 为什么「地址分网络 ID 与主机 ID」能让转发表变小又更稳定，域间与域内协议各看哪一段。
2. 默认路由匹配的顺序是什么，为什么端主机不需要参与路由协议。
3. 分类编址为什么失败，CIDR 用「任意长度的网络 ID」如何解决它。
4. 斜杠记法为什么容易看错，网络掩码又是怎么表示同一件事的。
